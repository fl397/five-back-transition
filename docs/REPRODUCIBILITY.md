# Reproducibility

## Environment
Python 3.12 (tested 3.12.13); `pip install -r requirements.txt` (numpy 2.2.6, pandas 2.2.3, scipy 1.13.1, statsmodels 0.14.4, scikit-learn 1.5.2, matplotlib 3.10.8, PyYAML 6.0.2, pyarrow). CPU only; the build parallelises over games (`--workers`, default 16).

## Stage 0 — from shipped aggregates (minutes, no external data)
```
python3 tests/test_smoke.py
```
Regenerates `figures/FIG1_recovery_clock.{png,pdf}` and `figures/FIG2_clock_vs_defenders.{png,pdf}` from `results/*.json` and asserts every headline number used in the abstract (games, starts, possessions, recovery clock, −17.3 pp and CI, +42.0 → +23.5, 44 %, dose response, 6–7 s bin rates, time-bin fixed-effects model).

## Stage 1 — from user-supplied public source data (~1 h on 16 cores)
See `scripts/run_all.sh` (documented download/placement instructions for the SportVU JSON mirror and the PlayByPlayV3 parquet; environment variables `FIVEBACK_SPORTVU_JSON`, `FIVEBACK_PBP`). Pipeline and analysis rules:

| step | producer | analysis rules | outputs |
|---|---|---|---|
| 1 | `src/build_fiveback.py` | `configs/analysis_definitions.yaml`: possession starts (defensive rebound of an opponent FGA miss; live-ball turnover = Turnover row paired with a STEAL row), corrected axis `tracking_clock = pbp_clock + 4.0 s` (and naive 0 s), attacking direction from made-FG ball position per team/period, `N_BACK` = defenders with x in their own half (midcourt 47 ft), first FGA ≤ 24 s with no intervening PBP event, FIVE_BACK read at 1.0 s before the shot (nearest frame ±0.06 s, else ±0.20 s) | `data/games/<game>.parquet`, `_traj.parquet`, `_meta.json` |
| 2 | `src/validate_nback.py` | construct validation thresholds (direction agreement, never-five-back share, monotonicity); must print PASS before any outcome | `results/nback_validation.json`, `audit/NBACK_VALIDATION.md` |
| 3 | `src/analyze_fiveback.py` | RIM_ATTEMPT = shotDistance ≤ 4 ft; linear probability models with restricted cubic spline on time into possession (knots at empirical p10/p50/p90 of the built sample), start type, period, score margin; MODEL D adds nearest-defender distance; time-only vs FIVE_BACK-only vs combined with 5-fold game-grouped CV log-loss; dose response ≤2/3/4 vs 5; game-clustered two-sided SEs; naive-vs-corrected classification | `results/fiveback_results.json`, `audit/PRIMARY_RESULTS.md`, `audit/NAIVE_VS_CORRECTED.md`, `data/shots_fiveback_{corrected,naive}.parquet` |
| 4–5 | `src/final_checks_build.py`, `src/final_checks_analyze.py --stage checks`, `src/final_checks_docs.py .` | `configs/final_adversarial_checks.yaml`: one-second time bins 4–10 s with overlap diagnostics and a time-bin fixed-effects model; ball frontcourt-entry time (first crossing of midcourt) and FC1/FC2 models; first-FGA selection taxonomy of all starts with the 6.0-s evaluation instant | `results/check1_common_support.json`, `check2_frontcourt_entry.json`, `check3_selection.json`, `final_checks_results.json`, `audit/CHECK*.md`, `audit/CHECK_SUMMARY.md` |
| 6 | `src/figures_final.py` | renders only from `results/*.json` | `figures/` |

Determinism: no random seeds are used except the fixed 5-fold `GroupKFold` split by game (deterministic given the game order); all rules were fixed before the corresponding numbers existed. `src/final_checks_analyze.py --stage gate --scratch <dir>` compares a regenerated results file against the shipped one field by field (`results/reproduction_gate.json`) (our own regeneration reproduced all 271 numeric fields with max |Δ| = 0.0).

## What cannot be reproduced without the source data
The −17.3 pp model, the recovery clock and the three checks need the shot/possession tables, which are derived from the tracking data and are withheld; they are regenerated by Stage 1. Everything shown in the figures and quoted in the abstract is reproducible from the shipped aggregates in Stage 0.
